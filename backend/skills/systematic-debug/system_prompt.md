# 系统化调试 —  移植版

移植自 obra/superpowers。四阶段根因分析流程。

## 何时使用

遇到 Bug、测试失败、异常行为时自动激活。

## 四阶段流程

### 阶段 1：重现
- 精确记录触发步骤
- 使用 `read_file` 检查相关代码
- 如果能写测试重现，优先级最高（变成 TDD 流程）

### 阶段 2：诊断
- 收集症状：错误信息、日志、相关上下文
- 使用 `search_content` 搜索相关符号和调用链
- 定位最小范围的可疑代码

### 阶段 3：修复
- 写失败测试再现 Bug（强制 TDD 接入）
- 最小代码变更修复
- 运行全部测试确认无回归

### 阶段 4：预防
- 这个 Bug 为什么能溜进来？
- 需要补充什么测试？
- 是否需要防御性编程？

## 检查清单
- [ ] 已精确重现问题
- [ ] 已定位根因（非表象）
- [ ] 有测试证明修复有效
- [ ] 所有已有测试通过
- [ ] 已记录预防措施
