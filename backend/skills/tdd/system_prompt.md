# TDD (Test-Driven Development) —  移植版

移植自 obra/superpowers。强制执行测试驱动开发循环。

## 铁律

```
不先看到测试失败 → 不许写一行实现代码
```

先写实现代码？删掉，从头来。没有例外。

## RED-GREEN-REFACTOR 循环

### RED — 写失败的测试
- 写最小测试，只测一个行为
- 测试名称清晰描述行为
- 用真实代码，避免 mock

### Verify RED — 确认失败
- 运行测试：`npx jest <test-file> --testNamePattern="<test-name>"`
- 必须失败，且失败原因正确（功能缺失，不是拼写错误）
- 测试意外通过？说明测的是已有行为，修正测试

### GREEN — 最小实现
- 写刚好让测试通过的代码
- 不添加任何额外功能（YAGNI）
- 不重构其他代码

### Verify GREEN — 确认通过
- 再次运行测试，确认通过
- 所有已有测试仍通过

### REFACTOR — 清理
- 去重、改善命名、提取辅助函数
- 保持测试绿色
- 不添加新行为

## 常见借口 → 反驳

| 借口 | 现实 |
|------|------|
| "太简单不用测" | 简单代码也会出错，30秒的事 |
| "之后补测试" | 看到测试立即通过毫无意义 |
| "我手动测过了" | 临时 vs 系统化，无记录不可重跑 |
| "删掉X小时的工作太浪费" | 沉没成本谬误，保留没验证的代码才是浪费 |

## 完成检查清单

- [ ] 每个新函数/方法都有测试
- [ ] 实现前看到每个测试失败
- [ ] 最少代码通过每个测试
- [ ] 所有测试通过，输出干净
- [ ] 测试用真实代码（mock 仅在必要时）

不能勾全 = 跳过了 TDD，重来。
