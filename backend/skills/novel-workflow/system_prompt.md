# 长篇小说 AI 辅助创作工作流

> 基于《断念剑》28 章 / 11.5 万字实战验证。适用任何长篇类型小说。

## 一、核心架构：内容与排版分离

### 铁律
```
❌ 不要把小说正文写进 Python 脚本
✅ 每章 = 一个独立 .md 文件，排版 = 一个轻量组装脚本
```

### 目录结构
```
项目文件夹/
├── story-bible.md          ← 创作总纲（写每章前必读）
├── STYLE.md                ← 风格约束
├── characters.yaml         ← 角色状态追踪
├── foreshadow.md           ← 伏笔追踪表
├── check_consistency.py    ← 一致性检查脚本
├── build_novel.py          ← 组装脚本（读取 .md → 生成 .docx）
└── chapters/
    ├── ch001.md
    ├── ch002.md
    └── ...
```

### 为什么这样做
- 单章扩写只改 4KB 的 `.md`，不改 30KB 的 `.py`
- 调试排版不需要重写内容
- 可并行写多章（每章独立加载 bible）
- 版本管理清晰（每章独立 diff）

## 二、五模块工程化系统

### 模块 1：story-bible.md（创作总纲）

**内容**：
- 世界观设定（规则、门派、能力体系）
- 全部角色档案（外貌/性格/弧线/关系/台词指纹）
- 卷章结构表（每卷核心事件+情感线进程）
- 伏笔清单（ID + 埋入章 + 计划回收章）
- 关键规则（能力铁律、设定边界）

**使用时机**：写每章前必读。每卷结束后更新一次。

### 模块 2：STYLE.md（风格约束）

**内容**：
- 文字风格（白描/句子节奏/对话规范）
- 禁用词清单（AI 腔标志词 + 替换方案）
- 打斗场景规则（情绪视觉化描写模式）
- 角色语言指纹（每人独特的说话特征）
- 章节结构规范（场景数/字数分布/钩子要求）

**使用时机**：写每章前必读。保持 120 章风格统一。

### 模块 3：characters.yaml（角色状态机）

**内容**：
- 每个角色的实时状态（位置/情绪/关系）
- 弧线进度百分比
- 关键物品追踪
- 伏笔背负标记

**使用时机**：每章写完后更新。避免写到第 60 章忘了第 3 章的角色状态。

### 模块 4：foreshadow.md（伏笔追踪表）

**内容**：
- 伏笔 ID + 内容 + 埋入章 + 计划回收章 + 状态（🌱/🌿/✅）
- 章节伏笔摘要矩阵

**使用时机**：每章写完后更新。埋了新伏笔→追加；回收了旧伏笔→标记✅。

### 模块 5：check_consistency.py（一致性检查）

**功能**：
- 名字拼写检测（标准名 vs 变体/错字）
- AI 腔禁用词扫描
- 能力设定冲突检测（正则匹配 + 否定排除）
- 字数统计（每章 + 总计）

**使用时机**：每章写完后运行。确保全绿通过再生成文档。

## 三、标准写作流程（单章）

### Step 1：加载上下文
```
read_file story-bible.md      # 世界观+人物+伏笔
read_file STYLE.md            # 风格约束
read_file characters.yaml     # 当前角色状态
read_file foreshadow.md       # 伏笔状态
```
如果续写：额外 `read_file` 上一章 `.md` 的末尾 30 行（确保衔接）。

### Step 2：撰写章节
```
write_file chapters/chXXX.md  # 4000+ 字
```
结构要求：
- 章标题（诗句格式）
- 引导诗（4 句五言/七言）
- 上回摘要（一句）
- 2-3 个场景（`* * *` 分隔）
- 章末钩子

### Step 3：更新状态
```
edit_file characters.yaml     # 更新角色位置/情绪/弧线进度
edit_file foreshadow.md       # 标记本章埋入/回收的伏笔
```

### Step 4：质量检查
```
run_command python check_consistency.py  # 必须全绿
```
常见修复：
- 名字警告 → 统一为标准写法
- 禁用词 → 替换为具体描写
- 设定冲突 → 检查是否为否定句误报

### Step 5：生成文档
```
run_command python build_novel.py  # → 断念剑.docx
```

## 四、常见坑与解决方案

### 坑 1：章节字数不达标
- **现象**：写完发现只 2,500 字
- **解决**：先写核心场景 → 再展开（扩环境描写、扩内心独白、扩配角反应）→ 用 `check_consistency.py` 统计
- **禁止**：灌水式扩写。每一段扩展都要有信息增量。

### 坑 2：edit_file 静默失败
- **现象**：search=replace 相同文本时返回成功但未修改
- **解决**：改用 Python 脚本操作文件（`write_file` 临时 .py → `run_command` 执行 → `delete_file` 清理）

### 坑 3：Python 命令行中文乱码
- **现象**：`run_command` 中嵌套中文代码报 SyntaxError
- **解决**：所有复杂 Python 操作先 `write_file` 写入 .py 文件 → `run_command python xxx.py`

### 坑 4：Word 文档被锁定
- **现象**：`PermissionError` — 文件被占用
- **解决**：输出文件加版本号（`_v2.docx`），不覆盖已打开的文件

### 坑 5：web_search 对英文技术词无效
- **现象**：搜索 "novel writing tool" 返回中文词典
- **解决**：改用中文关键词 + `web_fetch` 直接抓取已知 URL

## 五、批量写作策略

### 串行模式（稳定）
```
写第 N 章 → 更新状态 → 检查 → 生成 → 写第 N+1 章
```

### 并行模式（高效，需上下文隔离）
```
同时写 3 章：
  - 每章各自加载 bible + style + characters
  - 写完后统一 run check_consistency.py 检测冲突
  - 合并后更新状态
```

### 推荐节奏
- 单次会话：3-5 章（约 15,000-20,000 字）
- 每写完一卷（20 章）：更新 story-bible.md 的卷结构表
- 每 10 章：完整伏笔审计
