# 白圭投资理财能力强化方案 · 设计文档

> 版本：v0.1 草案 | 日期：2026-08-20 | 场景：data_analysis（白圭）| 状态：待评审
> 目标：让白圭能**清晰、精准、专业**地给出**符合用户风险偏好**的投资建议与资产组合。

## 决策记录（2026-08-20 评审 · 已落地批次1+2）

- **MCP 层：不新增**。用户已有同花顺 iFinD，基金/个股/宏观/债券数据已覆盖；沿用 `iFinD + mempalace + Searchpin`，不引多余依赖（契合"挖深不拓宽"）。§5 候选 MCP 全部搁置。
- **风险画像持久化：P1**（场景记忆 `risk_profile_v1` + KB 文档 `白圭-风险画像.md`，经 `harness.prompt_vars.risk_profile_summary` 常驻注入，不改 schema）。
- **实施范围：先做技能层（批次1+2）**，已落地并通过 pytest（37 passed）。
- 批次3（MCP 补齐）因决策"不新增"而**取消**；批次4（前端问卷 UI）暂缓，留作后续可选。

## 1. 现状诊断（基于代码事实）

### 1.1 白圭现有能力

| 维度 | 现状 | 证据 |
|------|------|------|
| 身份/人格 | `data_analysis` 技能，人格=战国商祖白圭，价值投资+逆向+纪律 | `skills/data_analysis/skill.yaml` L3、L11-13 |
| 绑定 MCP | `hexin-ifind-ds-*`（行情/财务/基金/债券/EDB）、`mempalace`、`Searchpin` | `config.yaml` L233-234 |
| 知识库 | `auto_retrieve: true`，含 `investment_framework.md`（财务/宏观/配置/纪律口径） | `skill.yaml` L46-49；`kb_assets/investment_framework.md` |
| 计算能力 | `code_execution` 已开（elevated），可做 pandas/numpy/matplotlib | `skill.yaml` L29-30, L62-63 |
| 输出规范 | 结论先行、数据来源、风险提示、免责声明已有 | `system_prompt.md` L55-62 |
| 持仓参考 | 规则要求"先取白圭场景记忆中的持仓概况" | `skill.yaml` L23；`system_prompt.md` L62 |

### 1.2 三大缺口（即用户诉求根因）

1. **风险偏好无结构性采集与持久化（核心缺口）**
   - 全代码库无 `risk_profile` / 风险画像字段；`user_profile` 表（`schema.sql` L176）仅存全局协作偏好（name/communication_style/common_tools…），**不含投资属性**。
   - `investment_framework.md` L73 写"风险偏好决定股债比例（保守30:70/均衡50:50/进取70:30）"，但"偏好"从未被采集、存储、注入 → 白圭每次只能**凭空假设**用户风险等级，输出与用户真实承受能力脱节。
2. **组合构建靠"写"不靠"算"**
   - 现有工作流是定性建议（比例/止损位用文字描述），未用 `code_execution` 对"实际持仓×实时行情"做**量化体检**（集中度、相关性、最大回撤、再平衡差额、目标权重偏离）。
   - 持仓数据仅存 MemPalace `securities_investing/portfolio`（非结构化），白圭靠 `memory_search` 提词，无程序化读取 → 组合数字常失真。
3. **建议模板不够"清晰专业"**
   - 输出规范偏散点（结论/来源/风险/免责各段分离），缺少**统一的"投资建议书"结构**：风险画像→当前组合体检→目标配置→再平衡动作清单→风险与免责，且缺少可计算的量化指标表。

> 结论：白圭"会分析单标的"，但"不会按我的风险偏好给我做组合"。本方案用**技能层（风险画像+组合引擎+输出规范）+ MCP层（补齐基金/个股精度）**双管齐下。

## 3. 总体方案：三层强化

```
┌─────────────────────────────────────────────────────────────┐
│ 层3 输出规范  统一"投资建议书"模板 + 量化指标表 + 行动清单      │
├─────────────────────────────────────────────────────────────┤
│ 层2 组合引擎  mempalace(持仓) × iFinD(实时价) → code_execution  │
│             → 体检 + 目标配置 + 再平衡差额（算，不是写）          │
├─────────────────────────────────────────────────────────────┤
│ 层1 风险画像  问卷采集 → 持久化 → 每轮注入 frozen/stable zone    │
│             → 驱动层2权重与层3语气                              │
├─────────────────────────────────────────────────────────────┤
│ 数据底座  MCP: iFinD(核心) + mempalace(持仓/KB) + Searchpin     │
│          【新增】晨星/企查查/东方财富妙想（见 §5，待用户决策）    │
└─────────────────────────────────────────────────────────────┘
```

### 3.1 层1 · 风险偏好画像系统

**采集（一次性问卷）**：白圭在首次进入投资场景或用户说"做组合/评估风险"时，用结构化问卷确定 5 个维度：

| 字段 | 取值/口径 | 用途 |
|------|-----------|------|
| `risk_level` | 保守/稳健/平衡/进取/激进（5档） | 决定战略股债比 |
| `horizon` | 投资久期（<1年/1-3年/3-5年/>5年） | 决定权益暴露上限 |
| `liquidity_need` | 高/中/低（近期是否用钱） | 决定现金缓冲比例 |
| `loss_tolerance` | 单笔最大可承受回撤（如 -10%/-20%/-30%） | 决定止损位与集中度上限 |
| `goal` | 保值/稳健增值/长期成长/激进收益 | 决定卫星仓风格 |

**战略股债比映射（写入 KB，供层2调用）**：

| 风险档 | 战略股:债 | 权益上限 | 单标的上限 | 现金缓冲 |
|--------|-----------|----------|------------|----------|
| 保守 | 30:70 | 40% | 5% | 15% |
| 稳健 | 40:60 | 55% | 8% | 10% |
| 平衡 | 50:50 | 70% | 10% | 8% |
| 进取 | 70:30 | 85% | 15% | 5% |
| 激进 | 85:15 | 95% | 20% | 3% |

**持久化（推荐方案 P1，轻量、无需改 schema）**：
- 画像以**结构化条目**写入白圭场景记忆（`user_memories`，scene=data_analysis），键 `risk_profile_v1`；
- 同步生成一份 `白圭-风险画像.md` 存入 data_analysis KB（`kb_assets/`），`auto_retrieve` 每轮命中；
- 在 `skill.yaml` 的 `harness.prompt_vars` 增加 `risk_profile_summary`，把当前画像摘要常驻注入，确保即使用户未主动问，白圭也按真实偏好给建议。
- （后续可选 P2：新增 `scene_profiles` 表 + 问卷 UI + admin API，支持程序化读取与前端编辑；本方案先不实施，避免 schema 迁移与前端工作量，符合"挖深不拓宽"。）

### 3.2 层2 · 资产组合构建与体检引擎

**触发**：用户请求"我的组合/资产配置/调仓/体检"时，白圭执行固定流水线：

1. **取持仓**：`mempalace` 读 `securities_investing/portfolio`（8只/¥457,440） → 得到标的、成本、数量。
2. **取实时价**：`iFinD` `get_stock_summary` / `stock_highfreq_quotes` 取现价、涨跌幅 → 算当前市值、盈亏、权重。
3. **算体检**（`code_execution`，pandas/numpy）：
   - 当前行业暴露、个股集中度（HHI / 前三大占比）；
   - 与 `risk_level` 目标权重的**偏离%**；
   - 再平衡买卖差额（目标市值 − 当前市值）；
   - 相关性（iFinD 取收益率序列算相关系数矩阵，识别"假分散"）；
   - 最大回撤估算（基于持仓波动率的组合 VaR/回撤近似）。
4. **出目标配置**：按 §3.1 战略比 + 核心-卫星（核心宽基60-70% + 卫星30-40%）生成目标权重，落到具体标的/ETF。
5. **出动作清单**：再平衡买卖额、止损位（绑定 `loss_tolerance`）、再平衡触发条件（偏离±5%或季度）。

> 关键：所有数字由 `code_execution` 算，**白圭只解释不编造**；图表（matplotlib）存 `outputs/` 并标注来源与时间。

### 3.3 层3 · 输出规范升级（"投资建议书"模板）

每份投资类输出统一结构（写入 `system_prompt.md` 输出规范段）：

```
① 风险画像（本次依据的风险档/久期/回撤承受力）
② 当前组合体检（量化指标表 + 集中度/相关性结论）
③ 核心观点（结论先行，一句话）
④ 目标配置（战略比 + 具体标的权重 + 与当前偏离）
⑤ 行动清单（再平衡买卖额 / 止损位 / 触发条件，可勾选执行）
⑥ 风险提示（市场/个股/流动性 + 免责声明）
```

新增 `examples/` 范例（注入 frozen_zone，L53 已支持 `max_examples:3`）：一份"组合体检+再平衡"示范、一份"单标的买入建议（带风险画像）"示范。

## 5. MCP 组合方案（待用户决策 · 配置类）

### 5.1 现有绑定（核心，保留）

`iFinD`（行情/财务/基金/债券/宏观EDB）+ `mempalace`（持仓+KB）+ `Searchpin`（交叉验证）。覆盖 A股/ETF/基金/宏观/债券，主力数据充分。

### 5.2 建议新增（三选组合，用户拍板）

| 候选 MCP | 补齐能力 | 贴合度 | 成本/注意 |
|----------|----------|--------|-----------|
| **晨星 morningstar** | 基金评级、十年长期业绩、基金经理稳定性、晨星风险系数 → 直击"基金分析精准化" | ★★★★★ | 国内免费档有限，部分深度数据需付费 |
| **企查查 qcc** | 个股工商/股权/司法/行政处罚风险 → 强化"个股风险"段，避免只看财务面 | ★★★★ | 已可用，需绑到 data_analysis |
| **东方财富妙想 mx-ds-mcp** | 研报/一致预期/财务预测/资金流向 → 补"催化与预期"维度 | ★★★★ | 国内免费档，覆盖面广 |
| （不推荐）Wind | 与 iFinD 高度重叠 | ★★ | 贵，边际收益低 |
| （不推荐）腾讯自选股 | 与 iFinD 行情重叠 | ★★ | 边际收益低 |

**推荐组合（A/B/C，供用户选）**：

- **A（推荐）**：晨星 + 企查查 —— 基金精度 + 个股风险双补，最贴合"精准专业"，边际收益最高。
- **B（全面）**：晨星 + 企查查 + 东方财富妙想 —— 在 A 基础上加研报/一致预期，覆盖"催化"维度，但需连3个、配置与限流成本上升。
- **C（最小）**：仅企查查 —— 先补个股风险，基金仍靠 iFinD，最快落地、最少依赖。

> 注：上述 MCP 当前在连接器状态均为 `disconnected`，需用户在连接器页连接；部分涉及付费套餐，连接前请确认额度。绑定方式：`config.yaml` 的 `skill_binding.data_analysis` 增加对应前缀（如 `mempalace` 同法加 `qcc-*`）。

## 7. 风险与未决项

1. **实时价依赖 iFinD 可用性**：iFinD 限流/断连时组合体检失真 → 层2 须带"数据时间戳+缺失提示"，不编造价。
2. **持仓数据非结构化**：MemPalace portfolio 抽屉格式若变，提取失败 → 建议后续把持仓落结构化（P2 `scene_profiles` 或专用持仓表）。
3. **MCP 付费/连接风险**：§5 新增项需用户先在连接器页连接并确认额度，AI 不擅自改配置（配置决策归用户）。
4. **回测近似非真实回测**：层2 最大回撤用波动率近似，非历史回测 → 输出须注明"估算"，不承诺历史表现。
