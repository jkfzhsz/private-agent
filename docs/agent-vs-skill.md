# 智能体（Agent）与技能（Skill）的概念界定

> 2026-08-05 立项，V1.5 规划项-3。本文是项目内"智能体 vs 技能"的权威认知文档，
> 供后续开发与文档编写时统一术语，避免混淆。

## 一句话结论

**Private Agent（本项目 PA）本身是一个智能体**；**Skill 是 PA 在工作时使用的一组技能**
（角色设定 + 系统提示词 + 工具配置）。二者是"主体"与"工具"的关系，不是并列概念。

## 概念对比

| 维度 | PA（智能体） | Skill（技能） |
|---|---|---|
| 定位 | 主体（agent）：感知 → 思考 → 决策 → 行动的完整智能体 | 工具/能力包：PA 在特定任务中调用的知识+行为模板 |
| 生命周期 | 常驻，跨会话存在（一个应用 = 一个智能体实例） | 可增删，按需加载；PA 加载某个 Skill 后按该技能的行为工作 |
| 构成 | ReAct 循环 + 记忆 + 知识库 + 工具系统 + 模型管理 | skill.yaml（名称/版本/描述）+ system_prompt.md（角色提示词）+ tools.yaml（工具白名单） |
| 类比 | 一个"员工" | 员工的"岗位手册/工作流模板" |
| 项目内落地 | `backend/private_agent/`（main / react_loop / tools / memory / knowledge） | `backend/skills/<skill_name>/` 目录 + `skills` 表（PG 运行时副本） |

## 常见混淆点澄清

1. **"切换技能" ≠ "切换智能体"**：PA 始终是同一个智能体；切换 Skill 只是给它换了
   "角色与工具集"（如：切到 `office` 技能后，PA 以秘书角色工作并解锁 office 相关工具）。
   底层仍是同一个 ReAct 循环、同一份长期记忆。

2. **视图命名**：前端 `AgentLibraryView.tsx` 是**历史遗留文件名**（V1.1 早期曾考虑
   "智能体包装"），2026-08-05 已做方向修正——UI 标题统一为"技能库"，代码注释明确
   "技能就是技能，不做智能体包装"。**后续重构可考虑将文件改名为 `SkillLibraryView.tsx`**
   （低风险纯改名，非本轮范围）。

3. **蓝图中的"智能体"表述**：蓝图（private-agent-blueprint.md）多处用"智能体"泛指
   本产品整体能力，不特指某个 Skill；阅读时按"PA 整体"理解。

4. **未来若引入子代理/任务委派（V1.5 规划项-1）**：子代理是 PA **临时派生**的工作实体
   （子任务执行者），仍与 Skill 不同——子代理是"执行单元"，Skill 是"能力定义"。
   届时文档需补充三者关系。

## 对开发的指导

- 新功能设计时先问："这是智能体**自身能力**（进核心，如记忆/推理），还是智能体
  **在特定任务中要用的**（进 Skill，如某行业术语/专用工具）？"
- Skill 目录只放"任务相关"内容；跨任务通用能力（搜索/文件/记忆）放核心工具层，
  不要塞进某个 Skill。
