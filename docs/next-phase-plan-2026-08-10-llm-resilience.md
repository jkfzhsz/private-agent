# LLM 调用韧性与上下文治理方案（2026-08-10）

> 背景：8-09/8-10 深度排查模型链路发现三类系统性问题——降级链单点、上下文注入不科学（图片只给路径、KB/状态栏/记忆抢 token、压缩丢事实）、错误静默（图片超限跳过、迭代用尽、上游错误吞掉）。蒋先生三点要求：① 双链（纯文本/多模态）按语境自动切换；② 上下文管理深入细化（压缩不丢事实/注入竞争/工具调用/窗口设定）；③ 错误零静默，分类暴露（设定/程序/能力边界/幻觉）。

## 一、双链架构（纯文本链 + 多模态链）

### 1.1 设计
- `config.yaml models.router` 新增 `text_chain` / `vision_chain`（向后兼容：未配置时 `fallback_chain` 同时充当两者）
  ```yaml
  models:
    router:
      fallback_chain: [deepseek-flash, deepseek-v4-flash, kimi-k2.6]  # 兼容旧配置
      text_chain: [deepseek-flash, deepseek-v4-flash]                  # 纯文本优先
      vision_chain: [kimi-k2.6]                                        # 多模态优先
  ```
- 链顺序由用户在设置页自由排列（底座不强制）——满足"链顺序是用户权利"

### 1.2 语境路由（ReactLoop）
- `require_vision`（含图/生图意图）→ 用 `vision_chain`
- 纯文本 → 用 `text_chain`
- **会话手动锁定**仍优先：锁定的模型若匹配当前语境则用之；不匹配（如锁纯文本却发图）→ **自动切对应链**（已实现，8-10 `924b410`），不再报错
- 生图场景预留：检测 LLM 调用图像生成工具/输出图片意图 → 走 vision_chain（当前 PA 无生图工具，架构预留）

### 1.3 实现
- `registry.build_fallback_chain` → 拆 `build_text_chain` / `build_vision_chain`
- `FallbackChain.has_vision` 已有（8-10）
- ReactLoop 按 `require_vision` 选链；会话锁定逻辑保留（锁定模型作为链首优先，语境不匹配时切链）
- 设置页增加双链配置 UI（text_chain / vision_chain 两个排序列表）

## 二、上下文管理重构（重中之重）

### 2.1 注入竞争治理
**问题**：KB 片段 + 状态栏 + 记忆 + 工具结果 + system prompt 多源注入抢 token，接近窗口时压缩频繁触发、上下文抖动。

**方案：注入预算 + 优先级**
- 每类注入设 token 上限（默认可配）：
  - system prompt：固定（Frozen Zone）
  - KB 片段：≤ 2000 token
  - 记忆注入：≤ 1000 token
  - 状态栏：≤ 500 token
  - 工具结果：≤ 4000 token（单条）
- 优先级（高→低）：用户当前消息 > 工具结果 > system prompt > KB > 记忆 > 状态栏
- 动态裁剪：构建消息时按优先级累计，接近窗口 70% 时低优先级注入截断/跳过
- 实现：`ContextManager.build_messages` 增加 `_inject_budget` 预算控制器

### 2.2 压缩不丢事实
**问题**：压缩摘要化事实性信息（持仓数字、账户、路径、约定、代码）→ 后续轮次答错（"记得不准"）。

**方案：事实检测 + 分级压缩**
- 事实型消息识别（启发式）：
  - 数字密集（≥3 个数值/比例）
  - 表格（| 分隔或多列对齐）
  - 路径（盘符/扩展名）
  - 代码块（``` 包裹）
  - JSON/结构化数据
  - 用户明确声明"记住/记录/这是"的消息
- 压缩策略：
  - **事实型消息：原文保留**（仅超长时截断尾部 + 标注"已截断，完整见存档"），不摘要
  - 非事实型（寒暄/闲聊/中间推理）：正常摘要
  - 事实型移入 `messages_archive`（已有表）可追溯
- 压缩提示词增强：明确要求"保留所有数字、路径、表格、代码原文"
- 实现：`Compressor` 加 `_is_factual(msg)` + 分级处理；压缩 prompt 强化

### 2.3 工具调用上下文膨胀
**问题**：file_read 大文件分块 → tool_result 累积 → 每轮全量重发历史工具结果 → token 指数增长。

**方案：工具结果摘要化 + 去重**
- 超长 tool_result（> 2000 token）→ 摘要 + 保留首尾 200 token + 原文存 `messages_archive`
- 工具结果去重：同一 tool_call_id 的结果不重复入上下文
- 分块读取（file_read offset）：仅保留最新块 + 索引（"已读 X-Y 行，共 Z 行"），历史块摘要
- 实现：tool_result 入库前过 `_summarize_tool_result`；ContextManager 加载时按策略恢复

### 2.4 上下文窗口动态化
**问题**：`context_window: 32768` 硬编码；不同模型窗口不同（kimi 128K、deepseek 64K）→ 窗口浪费或过早压缩。

**方案：per-provider 窗口 + 动态触发线**
- `resolve_provider_limits` 扩展 `context_window` 字段（provider 级覆盖全局）
- 压缩触发线 = 当前模型 `context_window * 0.8`（动态）
- 会话切换模型 → 触发线动态重算（已有每轮重建 adapter 机制，同步重算触发线）
- 实现：`resolve_provider_limits` 返回 context_window；`ContextManager` 用动态触发线替代硬编码

## 三、错误零静默（分类自然语言暴露）

### 3.1 原则
任何超越 LLM 能力边界或运行出错的情况，**禁止静默**，必须用自然语言暴露给用户，并标注分类，让用户分得清是哪类问题。

### 3.2 四类错误分类

| 分类 | 触发场景 | 暴露文案模板 |
|---|---|---|
| **【设定问题】** | 模型未配置/链空/key 缺失/权限拒绝/工具未注册 | "⚠️ 设定问题：[具体原因]。请[操作建议]。" |
| **【程序异常】** | 上游 5xx/超时/OOM/工具执行崩溃/WS 断连 | "⚠️ 程序异常：[类型]。已[处理]。可[重试/反馈]。" |
| **【能力边界】** | 模型拒答/迭代用尽/上下文超限/图片过大跳过/模型不支持图片 | "⚠️ 能力边界：[具体]。建议[替代方案]。" |
| **【幻觉误判】** | 不主动标（模型无法自检） | 提供"可追溯"：thinking 展开 + 工具结果可见 + 引用来源，让用户自行判断 |

### 3.3 具体暴露点（逐一对照当前静默点）

| 当前静默点 | 改为暴露 |
|---|---|
| 图片 >8MB 跳过注入 | emit "⚠️ 能力边界：图片过大（X MB，上限 8MB）未识别。请压缩后重发。" |
| 迭代用尽（max_iterations） | emit "⚠️ 能力边界：本轮已达步数上限（N 步）。建议拆分任务或换思路。" |
| AllProvidersFailedError | emit "⚠️ 程序异常：所有模型均失败（[provider 列表]）。最后错误：[摘要]。可重试。" |
| 工具执行异常（code_execution 崩溃） | emit "⚠️ 程序异常：工具 [name] 执行失败：[错误]。已跳过。" |
| 工具权限拒绝 | emit "⚠️ 设定问题：工具 [name] 被拒绝执行。" |
| 压缩失败 | emit "⚠️ 程序异常：上下文压缩失败，已降级为滑动窗口截断。" |
| KB 检索无结果 | emit（轻量提示）"未在知识库找到相关内容，基于模型自身知识回答。" |
| 模型返回空内容 | emit "⚠️ 能力边界：模型返回空内容。可重试或换模型。" |

### 3.4 实现
- 统一错误暴露层：ReactLoop 所有 `except` 分支 → 转自然语言 `final` 事件（带分类前缀）
- `_inject_image_urls` 超限/失败 → 返回跳过的图片列表 → ReactLoop emit 提示
- 工具执行层：`ToolExecutor` 异常 → 带 `[程序异常]` 标签回传
- 前端：error/final 事件渲染时识别 `⚠️ [分类]` 前缀 → 不同颜色/图标（设定=橙、程序=红、能力=蓝）

## 四、实施优先级与顺序

| 阶段 | 内容 | 理由 |
|---|---|---|
| **P0-A** | 错误零静默（3.3 全表） | 体验立竿见影，工作量集中（catch 分支改造），不改架构 |
| **P0-B** | 双链架构（1.1-1.3） | 基础设施，后续优化依赖；改动可控（registry + ReactLoop 选链） |
| **P1-A** | 上下文注入预算（2.1） | 缓解注入竞争，减少无谓压缩 |
| **P1-B** | 事实型压缩保护（2.2） | 直击"压缩丢事实"痛点 |
| **P2-A** | 工具结果摘要化（2.3） | 长工具链场景优化 |
| **P2-B** | 上下文窗口动态化（2.4） | 多模型窗口差异适配 |

### 验证策略
- P0-A：逐个静默点写测试（模拟触发 → 断言 emit final 含分类标签）
- P0-B：双链配置 + 语境路由测试（text/vision 各走对应链）
- P1：压缩事实保护测试（持仓数字/路径/表格压缩后原文保留）
- 端到端：白圭持仓对话长链路（发图→识别→记录→多轮调整→压缩→事实不丢）

## 五、不做什么（边界）

- **不做中转双活**：模型生态自然解决，链顺序是用户权利
- **不做模型选型推荐**：底座只提供双链 + 语境路由，选哪个模型由用户配置
- **不做幻觉检测**：模型无法自检幻觉，靠"可追溯"（thinking + 工具结果 + 引用）让用户判断
- **不做提示注入防御**：权限确认是防线（确认疲劳另议），注入检测超出底座范围
